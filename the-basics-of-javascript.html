    Let’s discuss the differences between PHP and ECMAScript 6 code with the [use strict] declaration (line 1):

    • The first difference is that in ECMAScript, variables are declared using the following keywords:
      • [let] to declare a variable whose value may change during code execution;
      • [const] to declare a variable whose value will not change (i.e., a constant) during code execution;
      • You can also use the [var] keyword instead of [let]. This was the keyword used in ECMAScript 5. We will not use it in this course;
    • line 6: the [console.log] method can display all kinds of data: strings, numbers, booleans, arrays, and objects. The PHP [print] method cannot natively display arrays and objects. In the [console.log] expression, [console] is an object and [log] is a method of that object;
    • line 8: JavaScript arrays are objects referenced by a pointer. When we write: 
    
const array = ["one", "two", 3, 4];

    the variable [array] is a pointer to the literal array ["one", "two", 3, 4]. Modifying the array’s contents does not change its pointer. Therefore, an array is most often declared with the [const] keyword. In PHP, an array is not referenced by a pointer. It is a literal value;

    • Line 12: The loop variable [i] is declared (let) within the loop. The keyword [let] is block-scoped (code within curly braces). Therefore, the variable [i] on line 12 is only accessible within the loop;
    • Line 18: The string concatenation operator is the + operator in JavaScript and the . operator in PHP. A distinctive feature of this operator is that it takes precedence over the + addition operator. Thus:
      • in PHP, ‘1’ + 2 yields the number 3;
      • in JavaScript, ‘1’+2 yields the string ‘12’;
    • line 20: [console.log] can display arrays;
    • line 82: in JavaScript, it is not possible to specify the type of a function’s parameters;
    • line 91: the [typeof] operator allows you to determine the type of a data item. There are four types: number, string, boolean, and object. Note that in JavaScript there is no [integer] type or [array] type. As mentioned, arrays are handled via pointers and fall into the object category;
    • lines 50–59: As in PHP, JavaScript has two comparison operators, == and ‘===’, with the same meaning as in PHP. ESLint most often flags the == operator as a potential error. We will consistently use the ‘===’ operator;
    • line 79: we could have included the [return] statement, but ESLint issues a warning that [return] should only be used within a function;

    The script [bases-03] examines the scope of variables in JavaScript:

    
'use strict';
// variable scope
let count = 1;
function doSomething() {
  // count is known here
  console.log("count=", count);
}
// call
doSomething();
    • the variable [count] declared outside the [doSomething] function is nevertheless known within this function. This is a fundamental difference from PHP;

    3.4. script [bases-04]

    A local variable hides a global variable with the same name:

const count = 1;

  // the local variable hides the global variable

    3.6. script [bases-06]

    The keywords [let] and [const] define variables with [block] scope (code within curly braces), but not the keyword [var]:

    
'use strict';
// the [let] keyword allows you to define a block-scoped variable
{
  // the variable [count] is only known within this block
  let count = 1;
  console.log("count=", count);
}
// Here, the variable [count] is not known
count++;

// the keyword [const] allows you to define a block-scoped variable
{
  // the variable [count2] is only known within this block
  const count2 = 1;
  console.log("count=", count2);
}
// here the variable [count2] is not known
count2++;

// the keyword [var] does not allow defining a block-scoped variable
{
  // the variable [count3] will be known globally
  var count3 = 1;
  console.log("count=", count3);
}
// here the variable [count3] is known
count3++;

    Comments

    • line 5: the variable [count] is only known within the code block in which it is declared (lines 3–7);
    • line 14: the constant [count2] is only known within the code block in which it is declared (lines 12–16);
    • line 23: the variable [count3] is known outside the code block in which it is declared (lines 21–25);

    ESLint reports the following errors:

    For these reasons related to block scope, we will only use the keywords [let] and [const] from now on.

    This script demonstrates the possible type conversions in JavaScript.

    
'use strict';

// implicit type conversions
// type --> bool
console.log("---------------[Implicit conversion to a boolean]------------------------------");
showBool("abcd");
showBool("");
showBool([1, 2, 3]);
showBool([]);
showBool(null);
showBool(0.0);
showBool(0);
showBool(4.6);
showBool({});
showBool(undefined);

function showBool(data) {
  // The conversion of data to a boolean is done automatically in the following test
  console.log("[data=", data, "], [type(data)]=", typeof (data), "[boolean value(data)]=", data ? true : false);
}

// Implicit type conversions to a numeric type
console.log("---------------[Implicit conversion to a number]------------------------------");
showNumber("12");
showNumber("45.67");
showNumber("abcd");

function showNumber(data) {
  // data + 1 doesn't work because JavaScript performs string concatenation instead of addition
  const number = data * 1;
  console.log("[data=", data, "], [type(data)]=", typeof (data), "[number]=", number, "[type(number)]=", typeof (number));
}

// Explicit type conversions to a boolean
console.log("---------------[Explicit conversion to a boolean]------------------------------");
showBool2("abcd");
showBool2("");
showBool2([1, 2, 3]);
showBool2([]);
showBool2(null);
showBool2(0.0);
showBool2(0);
showBool2(4.6);
showBool2({});
showBool2(undefined);

function showBool2(data) {
  // The conversion of data to a boolean is done explicitly in the following test
  console.log("[", data, "], [type(data)]=", typeof (data), "[boolean value(data)]=", Boolean(data));
}
// Explicit type conversions to Number
console.log("---------------[Explicit conversion to a number]------------------------------");
showNumber2("12.45");
showNumber2(67.8);
showNumber2(true);
showNumber2(null);

function showNumber2(data) {
  const number = Number(data);
  console.log("[data=", data, "], [type(data)]=", typeof (data), "[number]=", number, "[type(number)]=", typeof (number));
}

// to String
console.log("---------------[Explicit conversion to a string]------------------------------");
showString(5);
showString(6.7);
showString(false);
showString(null);

function showString(data) {
  const string = String(data);
  console.log("[data=", data, "], [type(data)]=", typeof (data), "[string]=", string, "[type(string)]=", typeof (string));
}

// some unexpected implicit conversions
console.log("---------------[Other cases]------------------------------");
const string1 = '1000.78';

console.log("data1=", data1, "type=", typeof (data1));

console.log("data2=", data2, "type=", typeof (data2));

console.log("data3=", data3, "type=", typeof (data3));

console.log("data4=", data4, "type=", typeof (data4));
// false is converted to the number 0
const data5 = false * 1.18;
console.log("data5=", data5, "type=", typeof (data5));
